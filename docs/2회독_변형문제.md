# 2회독 변형문제 (유형 A / B)

지문 1개 → 유형 A 세트, 유형 B 세트를 **각각 따로** 생성한다.
A·B는 프롬프트도 캐시도 템플릿도 완전히 별개다.

---

## 1. 파일 지도 — 뭘 고치면 뭐가 바뀌나

```
variation/                     ← 파이썬 로직
├── prompts.py     (2,083줄)   SYSTEM_PROMPT_A / SYSTEM_PROMPT_B + 보조 프롬프트
│                              → 문항 내용·품질을 바꾸려면 여기
├── generator.py   (3,779줄)   Claude 호출 + 재시도 + 후처리 + 캐시 키
│                              → 생성 흐름·캐시·검증 연결
├── validator.py   (1,046줄)   validate_a / validate_b — 산출물 무결성 검사
│                              → "이런 건 걸러야 해"는 여기
├── vocab_q3.py    (1,567줄)   A Q3 어휘 밑줄 자리 선정·검증·인덱스 보정
├── renderer.py      (601줄)   JSON → HTML (A·B 템플릿 결합, 로고 data URI)
└── api.py           (304줄)   /api/variation, /item, /cache-status, /clear-cache

★ 시험지 템플릿은 variation/ 폴더가 아니라 저장소 루트에 있다:
variation.html    (595줄)  유형 A 시험지 + 답지
variation_b.html  (569줄)  유형 B 시험지 + 답지
```

`renderer.py`는 루트를 템플릿 디렉터리로 잡고 `env.get_template("variation.html")`로 불러온다.
**레이아웃·문구·색상을 바꾸려면 파이썬이 아니라 이 HTML 두 개를 고쳐야 한다.**

**역할 분담 원칙** (코드 주석에 명시): **의미 판단은 전부 LLM, 코드는 검증만.**
어느 단어에 밑줄 칠지·동의어를 뭘로 쓸지는 LLM이 정하고,
자리가 유효한지·인덱스가 맞는지·중복이 없는지는 코드가 본다.

## 2. 유형 A — `variation.html`

2단 레이아웃. 왼쪽에 지문과 객관식, 오른쪽에 일치판단·서술형, 아래 MEMO 박스.

| 번호 | 문항 | 발문 | 데이터 키 |
|---|---|---|---|
| Q1 | 주제 | 다음 글의 주제로 가장 적절한 것은? | `topic_options`, `topic_correct` |
| Q2 | 순서 | intro + (A)(B)(C) 순서배열 | `paragraphs`, `order_correct` |
| Q3 | **어휘 또는 핵심빈칸** ↓ | | |
| Q4 | 불일치 | 일치하지 **않는** 진술의 **개수는?** (①1개~⑤5개) | `statements`, `mismatch_count` |
| Q5 | 빈칸 영작 | 빈칸 (A)(B)를 &lt;보기&gt; 단어를 모두 써서 완성 | `blank_A`, `blank_B`, `bogi` |

### Q3 어휘의 구조 — 넷은 유의어, 하나만 반의어

지문에 밑줄 5개를 치는데, **넷은 원문을 유의어로 바꾸고 하나(정답)만 반의어로 뒤집는다.**
학생은 문맥상 이상한 하나를 고른다.

여기서 따라오는 결론이 중요하다:
- 유의어로 바뀐 넷은 **의미가 안 변하므로 다른 문항 판정에 영향이 없다.**
- **반의어로 뒤집힌 정답 자리만** 다른 문항(Q4·Q5)과 충돌할 수 있다.

`_s158`·`_s159` 수정이 전부 이 전제 위에 서 있다.

### Q3는 둘 중 하나만 나온다 (배타적 분기)
```jinja
{% if item.data.vocab_items %}      → Q3.어휘 (수능 30번형 밑줄 5개)
{% elif item.data.core_blank_options %} → Q3.핵심빈칸 (5지선다)
{% endif %}
```
`vocab_items`가 있으면 어휘, 없으면 핵심빈칸으로 폴백한다.
**어휘 생성이 실패하면 조용히 핵심빈칸으로 바뀌는 구조**라, 어휘가 안 나올 때 이 분기를 먼저 볼 것.

### Q2 순서 — 고정 5선지
```
0=(A)-(C)-(B)  1=(B)-(A)-(C)  2=(B)-(C)-(A)  3=(C)-(A)-(B)  4=(C)-(B)-(A)
```
정답이 `(A)-(B)-(C)`인 경우는 없다(반드시 셔플).
**`intro + (A)(B)(C)` = 원문 전체**여야 한다 — 중복도 누락도 안 된다. 과거 최대 버그.
문장 경계에서만 자르고, 원문에서 안 붙어 있던 문장을 한 블록에 묶지 않는다.

### 안내문·공고문은 문항 구성이 다르다
수능 27·28번형은 `is_notice()`가 잡아내 `layout = "notice"`로 표시하고
**주제(1) · 불일치(2) · 빈칸영작(3) 3문항**만 낸다.
항목 나열이라 순서를 섞어도 논리가 안 깨지고, 방향을 가진 낱말이 없어 어휘가 성립하지 않기 때문.
(실측: 27번이 3회 연속 생성 실패했고 원인이 전부 Q3 어휘였다 — `_s152`)

템플릿에서 `{% set _notice = (item.data.layout == 'notice') %}` 로 받아
문항 번호와 발문("다음 안내문의 …")까지 같이 바꾼다.

## 3. 유형 B — `variation_b.html`

객관식 3 + 서술형 2. 색상 테마가 A와 다르다(`--teal`, `--purple` 중심).

| 번호 | 문항 | 발문 | 데이터 키 |
|---|---|---|---|
| Q1 | 문장위치 | 주어진 문장이 들어가기에 가장 적절한 곳은? | `given_sentence`, `passage_with_marks`, `position_correct`, `position_count` |
| Q2 | 제목 | 다음 글의 제목으로 가장 적절한 것은? | `topic_options`, `topic_correct` |
| Q3 | 요약빈칸 | 한 문장 요약의 (A)(B)로 적절한 것은? | `summary_template`, `summary_options`, `summary_correct` |
| Q4 | **어법** | 윗글의 어법상 틀린 곳 한 군데를 찾아 고치고 이유 쓰기 | `grammar_q4` (`correct`/`wrong`/`point`/`why`) |
| Q5 | 주제 영작 | &lt;보기&gt;로 주제문을 영작 | `topic_writing_bogi`, `topic_writing_answer` |

- Q1 마커는 `<MARK1>`~`<MARK5>`. 지문이 짧으면 `position_count = 4`로 줄어든다.
- **Q3의 (A)(B)는 반드시 각각 한 단어**(구·공백 불가). 다섯 (A)가 모두 다른 단어, 다섯 (B)도 모두 달라야 한다.
- 요약문은 **한 문장을 패러프레이즈한 게 아니라 지문 전체 논지를 새로 압축한 문장**이어야 한다(수능 40번 방식).
- `summary_design` 5행 구조: `정답` / `유의어-A` ×2 / `유의어-B` / `둘다틀림`.
  각 행을 실제 문장으로 써 봐야 복수정답이 드러난다 — 프롬프트가 이걸 강제한다.
- 한국어 해석은 **평서체 `~한다/~이다`**. `~합니다/~입니다` 금지.
- **Q4는 `_s161`에서 요약영작을 폐기하고 어법으로 바꿨다** — 아래 8절 참조.
  보기(`<보기>`)가 없는 문항이고, 답란은 세 칸이다(틀린 표현 / 바르게 고친 것 / 이유).
  이유는 자유 서술이고 답지에 **모범답안**이 실린다.

## 4. 생성 파이프라인

```
지문(passages) → 캐시 조회 → (없으면) Claude 호출 → validate_a / validate_b
                                    ↑                        ↓ 실패
                                    └──── 최대 3회 재시도 ─────┘
                                                             ↓ 통과
                                        후처리 → step_cache 저장 → 렌더
```

**문항 내부 생성 순서 — 이게 여러 버그의 뿌리다:**
```
Q5 빈칸 선정 → Q3 어휘 선정 → Q4 진술 생성 → 검증 → (실패 시 재시도)
```
빈칸이 어휘보다 **먼저** 뽑히므로, 빈칸을 뚫는 시점에는 Q3 정답이 뭔지 알 수 없다.
그래서 겹침은 어휘가 확정된 뒤에 **코드가 빈칸을 옮겨서** 푼다(API 재호출 아님).

- `MAX_RETRIES = 3`, 모델은 `CLAUDE_MODEL` 환경변수
- 마지막 재시도는 `strict=False` / `lenient=True`로 완화 검증
- `cache_only=True`면 캐시에 없어도 생성하지 않고 `None` (합치기 단계 타임아웃 방지)
- 캐시 히트 시에도 `note_answer_word()`로 '이미 쓴 단어'를 기록한다 (같은 강 내 중복 방지)

## 5. ⚠️ 반드시 지킬 것

### ① 프롬프트나 생성 로직을 고치면 캐시 버전을 올려라
`generator.py`의 `make_cache_key()` 위에 버전이 **하드코딩**돼 있다.
`_s161`부터 **유형별로 갈라져 있다**:
```python
_A_VER = "s160"
_B_VER = "s161"
...
_ver = _B_VER if str(variation_type).lower() == "b" else _A_VER
return f"{prefix}{txt_hash}_var{variation_type}_{_ver}"
```
안 올리면 **옛 캐시가 그대로 나와서 수정이 반영 안 된 것처럼 보인다.**

**★ 고친 쪽 것만 올려라.** 예전처럼 한 줄로 묶여 있으면 B를 고쳐도 A 캐시 899건이
같이 무효화돼 재생성 크레딧을 태운다. B만 고쳤으면 `_B_VER`만 올린다.

캐시 키 구조: `{책15자}_{단원8자}_{번호6자}_{본문md5 8자}_var{a|b}_s{버전}`
예) `공통영어2_능률(오)_01과_05번_ad9e0a94_vara_s160`

**★ 실패한 문항은 캐시에 안 남는다.** 그래서 코드만 고치면 다음 생성부터 바로 반영된다.
버전을 올려야 하는 건 **통과해서 이미 저장된 것**을 갈아엎을 때다.

### ② `generator.py`와 `vocab_q3.py`는 항상 같이 올려라
한쪽만 올리면 `import` 실패로 **검사가 통째로 안 도는데 아무 일도 없는 것처럼 배포된다.**
실제로 겪은 사고다(`_s151` 주석).

### ③ 실패는 시끄러워야 한다
`except Exception: pass`로 검사를 삼키지 말 것. 반드시 `print("⚠ 검사 건너뜀 …")`을 남긴다.
**"검사대가 있는 줄 알았는데 없었다"** 가 이 코드베이스에서 가장 자주 난 사고 유형이다.
(`_s135`, `_s140`, `_s151` 전부 같은 유형)

### ④ 주석의 `_sNNN`은 지우기 전에 읽어라
코드 곳곳의 `_s95`, `_s151`, `_s156` 등은 **그 변경이 있었던 작업 회차**다.
101개가 쓰였고 현재 최신은 `_s161`. 대부분 실측 사고에서 나온 방어 코드이고,
왜 그렇게 짰는지가 그 주석에 다 적혀 있다. 이상해 보여도 먼저 읽을 것.

### ⑤ `is_last` 탈출구 — 마지막 시도에서 검사 6개가 꺼진다

`generator.py`에 `and not is_last`로 묶인 검사가 **여섯 개** 있다.
`is_last`는 3번째(마지막) 시도이고, **거기서는 전부 꺼진 채 그대로 산출물이 나간다.**

실제로 `_s158` 사고가 이 길로 새어 나갔다 — 가드는 있었는데 마지막 시도에서 꺼졌고,
로그도 안 남아서 아무도 몰랐다. 실측 22파일 58문항 중 7건.

지금은 무엇을 봐줬는지 로그를 남긴다:
```
[VAR][A][01번] ⚠⚠ 관대 모드로 내보냄 — 봐준 결함: Q3 정답이 Q5 빈칸과 같은 문장
```
**이 로그가 뜨면 그 산출물은 검수 대상이다.**

새 검사를 넣을 때는 `is_last`로 빠져나갈 수 있는지 먼저 확인할 것.
정말 막아야 하는 것이면 재시도가 아니라 **코드가 직접 고치도록** 짜야 한다(`_s158` 방식).

### ⑥ 원문은 한 글자도 건드리지 않는다
`vocab_q3.py`는 원문을 수정하지 않고 **인덱스만 기록**한다.
이 설계 덕분에 Q2 순서 복원 검증이 성립한다. 마커 삽입·원복 왕복을 도입하지 말 것.

### ⑦ 내부 마커가 산출물로 새면 안 된다
`<BLANK_A>`, `<BLANK_B>`, `<CORE_BLANK>`, `[[[...]]]` 는 전부 코드 내부용이다.
과거에 LLM이 이 가림 문자열을 근거 인용문에 그대로 베껴 **답지에 찍힌 사고**가 있었다(`_s150`).
지문(`paragraphs`)은 마커를 담는 게 정상이므로 검사에서 제외한다.

### ⑧ 규칙을 새로 조일 때는 반드시 '후보 소진 검사'를 같이 한다

빈칸·밑줄 자리 규칙을 조이면 **뽑을 자리가 없어져 지문이 통째로 누락된다**(`_s112` 사고).
실제 단락으로 돌려서 후보가 0이 되는 단락이 없는지 확인할 것.

```python
from variation.generator import _q5_candidates
len(_q5_candidates(passage_text))   # 0이 되는 지문이 있으면 규칙이 과하다
```
`_s160` 검증 실측: 실제 지문 14개(짧은 것 위주 = 최악 조건)에서
후보가 42→40, 69→66 식으로 소폭만 줄고 **0이 된 지문 0개.**

## 6. 캐시 — Supabase `step_cache`

**변형문제 캐시는 `step_cache` 테이블에 들어간다.**
`step_name = 'variation_a'` 또는 `'variation_b'`.

⚠️ `variation_cache` 라는 테이블이 따로 있지만 **0행이고 아무도 안 쓴다(죽은 테이블).**
함수 이름이 `fetch_variation_cache_rows()`, `delete_variation_cache()` 라서 헷갈리는데,
실제로 읽고 쓰는 건 전부 `step_cache`다.

캐시 조회·삭제는 `make_cache_key_prefix()`가 만든 **앞부분(`{책}_{단원}_{번호}_`)으로 훑는다.**
본문 md5와 버전은 바깥에서 알 수 없기 때문 — 덕분에 본문이 바뀌어 남은 옛 캐시까지 같이 잡힌다.

관련 API: `POST /api/variation/cache-status` (준비됨/미생성 표시), `POST /api/variation/clear-cache`
페이로드는 둘 다 `{"passages": [{"book","unit","id"}, ...]}`.

## 7. 인쇄 레이아웃 (A·B 공통 규칙)

- `@page { size: A4; margin: 11mm 13mm 14mm 13mm; }`
- 본문 기준 `font-size: 9.5pt`, `line-height: 1.55`
- 지문 영역 `9pt`, 헤더 제목 `11.5pt`
- 지문+문항 2단: `display: grid; grid-template-columns: 1fr 1fr; gap: 0 12px;`
- 지문 1개 = 1페이지 (`page-break-after: always`)
- 답지는 `.ans-block`에 `page-break-inside: avoid`
- 색상은 `:root` CSS 변수로 통일 — `--primary #1A3A6B`, `--accent #28527D`,
  `--purple #3D4C7A`, `--teal #1F5276`, `--red #B91C1C`
- 로고는 `static/logo2.png`를 base64 data URI로 인라인 (외부 요청 없음)

`renderer.py`가 A·B 각 템플릿의 `<style>`을 **양쪽 다 보존**한 채
`<section class="variation-section">`으로 감싸 격리한다. 클래스명이 겹치지 않게 주의.

## 8. 최근 수정 이력 (`_s158` ~ `_s161`)

방향이 서로 반대라는 점에 주의 — 무조건 조이는 게 답이 아니다.

| 수정 | 방향 | 이유 |
|---|---|---|
| `_s158` Q3 ↔ Q5 | **조임** | 학생이 두 문항을 한 판단으로 풀어버린다. 진짜 겹침. |
| `_s159` Q3 ↔ Q4 | **품** | Q3 오답 넷은 유의어라 대부분 무해. 재시도만 태우고 있었다. |
| `_s160` 빈칸 절 경계 | **조임** | 복원 단서가 사라져 문항이 성립하지 않는다. |
| `_s161` B Q4 유형 교체 | **바꿈** | 조여도 풀어도 안 되는 겹침이었다. 문항 자체를 갈았다. |

### `_s158` — Q3 정답과 Q5 빈칸이 같은 문장
한 문장이 3번 정답이면서 동시에 5번 빈칸이었다(실측 58문항 중 7건).
가드는 있었으나 `is_last`로 꺼졌다.
→ 재시도가 아니라 **코드가 빈칸을 옮긴다.** `pick_a_q5_blanks(..., avoid=[...])`,
  `vocab_q3.answer_sentence_span()`, `data["_paras_preblank"]` 추가.
  **보기(bogi) 생성 직전**에 재선정해야 보기가 안 어긋난다 — 순서가 중요하다.
  거리 1(옆 문장) 34건은 손대지 않았다. 문장이 다르면 근거도 달라 답이 안 갈린다.

### `_s159` — Q3↔Q4 겹침 판정을 좁힘
`q4_conflicts_with_answer()`가 문장 내용어 70% 겹침만 보고 튕겼다.
Railway 로그 실측: **Q3 어휘 재시도 60건 중 19건(32%)이 이 검사 하나 때문**이었고,
그 결과 8개 지문이 관대 모드로 넘어갔다 — 막으려던 결함이 그 길로 나갔다.
→ **진술 본문에 그 낱말이 있을 때만** 충돌로 본다. `statements=` 파라미터 추가.
  어족 판정은 `_kin_word()` — 어미 목록으로 자르면 `difficulty`의 `ly`가 부사로 잘려
  `difficult`와 안 맞는다(실측). 앞에서부터 겹치는 길이로 본다.

### `_s160` — 쉼표 없이 절이 이어질 때의 빈칸 잘림
**주절과 다른 절을 한 빈칸으로 뚫지 말 것**(반복 강조된 규칙).
기존 `crosses_clause()`는 쉼표를 찾아 판정해서, 쉼표가 없으면 통과했다.
```
원문   … is up to you but [your dot map] should show …
시험지 "is ⬜ should show"   → 둘째 절 주어만 빈칸 안, 술부는 밖. 복원 불가.
```
등위 명사구(`soil and water pollution`)와 형태가 같아 구절만으로는 판정 불가 —
**빈칸 밖**이 동사면 절 잘림이다. 그래서 지문을 같이 받는다: `clause_tail_cut(span, ptext)`.
**픽 경로 셋 다 걸어야 한다** — `_q5_candidates` / `validate_llm_q5_spans` /
`pick_a_q5_blanks._valid_llm`. 하나라도 빠지면 규칙이 통째로 우회된다(`_s48` 교훈).
불규칙 과거형(`knew` `said` `took`)은 동사 판정에 넣고, 현재형 원형(`break` `show`)은
명사로도 흔해 뺐다.

### `_s161` — B Q4를 요약영작에서 어법으로 갈아엎음

**Q3 요약빈칸과 Q4 요약영작이 구조적으로 겹쳤다.** 둘 다 "지문을 한 문장으로 요약"인데
지문의 논지는 하나뿐이다. 프롬프트로 "결을 다르게 하라"고 지시해 놨는데도 안 갈라졌다 —
갈라질 수가 없는 요구였다.

결과는 재시도 폭주였다. Railway 로그 실측(Further Reading 지문): **겹침 검사에 걸려
11회 재시도**, 끝내 통과 못 하고 지문이 통째로 빠진 산출물이 나갔다.
겹침 검사를 풀면 학생이 3번을 푼 답을 4번에 그대로 베껴 쓴다. 조여도 풀어도 안 됐다.

→ **문항 유형을 바꿔 겹침의 원인을 없앴다.** 지문 어딘가에 어법 오류를 딱 한 곳 심고,
학생이 찾아서 고치고 그렇게 고친 이유를 쓴다. 요약 능력이 아니라 어법 능력을 묻는다.
겹침 검사 자체가 필요 없어졌다.

| 항목 | 내용 |
|---|---|
| 난이도 | **수능 영어 29번** 수준 — 구조를 읽어야 보이는 자리 |
| 오류 개수 | **한 곳.** 다섯 개를 표시하지 않는다 |
| 학생이 쓰는 것 | 틀린 표현 / 바르게 고친 것 / 그렇게 고친 이유(자유 서술) |
| 답지 | `틀린 표현 → 고친 것 [어법 이름]` + `이유(모범답안)` |
| 데이터 키 | `grammar_q4` = `{correct, wrong, sentence, point, why}` |

**출제 관점은 1회독 Lv.8-1 어법 괄호형에서 가져왔다.** 형식은 다르지만(저쪽은 괄호쌍
여럿, 이쪽은 오류 하나) 무엇을 출제하고 무엇을 버리는가는 같아야 한다.
프롬프트(`build_grammar_error_prompt`)에 등급 S/A/B 와 금지 필터 C1~C5 가 그대로 들어 있다.

- **S** 전치사+which / that vs what / 동격 that / so·such ~ that / 본동사 vs 준동사 /
  분사구문 / 멀리 떨어진 주격관계대명사
- **A** 후치수식 능수동 / 같은 어근 형용사·부사 / 1형식+부사 / 2형식+형용사 /
  to부정사·동명사 목적어 / couldn't help but / one of + 복수명사
- **B** 멀리 떨어진 수일치 / 학문명 -ics / A number of·The number of / 상관접속사

버리는 자리 — **C1** 두 형태가 다 맞는 자리(start + to V/V-ing, 주격 that/which),
**C2** 어휘·의미 차이(시제·부정·접두사·불가산명사에 s·철자·관사),
**C3** 바로 옆 힌트(조동사 뒤, 주어 바로 뒤 수일치), **C4** 원문에 없는 자리,
**C5** 성별 불명확 대명사. 거리는 **2토큰 이상**이 원칙이다.

★ **개수 부족 < 잘못된 어법 출제.** 좋은 자리가 없으면 쉬운 S/A 자리로 내려간다.
금지 필터에 걸리는 자리로 채우지 않는다.

**심는 순서가 중요하다.** 반드시 **Q1 위치 정정(원문 복원 검증)이 끝난 뒤에** 심는다.
먼저 심으면 `passage_with_marks` 가 원문과 달라져 Q1 정답 계산이 깨진다.

**낱말 경계** — `correct` 가 `is` 같은 한 낱말일 때 `in` / `.count()` 로 세면
`this` 안의 is 까지 잡는다. "지문에 두 번 나온다"고 잘못 거부하거나 엉뚱한 자리에
오류를 심는다. 수일치 문항이면 거의 매번 걸린다.
→ `validator.grammar_span_re / grammar_count / grammar_replace_once` 로 통일했다.
generator·validator·검수 스킬이 전부 같은 함수를 쓴다.

**캐시** — 옛 B 캐시 831건에는 `grammar_q4` 가 없다. 새 템플릿으로 렌더하면
4번 답란과 답지 어법행이 **통째로 빈 채 인쇄된다.** 그래서 B 버전을 올렸다.
A 는 이번 수정과 무관하므로 `_s160` 그대로 뒀다(위 5절 ① 참조).
산출물에 **요약문이 두 개** 보이면 옛 캐시다.

## 9. 해결됨 — B 보기가 정답 순서 그대로 나가던 문제 (`_s161`)

**유형 B의 서술형 문항이 사실상 무력화돼 있었다.**
`<보기>` 단어가 정답 순서 그대로 제시돼서, 학생이 왼쪽부터 옮겨 적으면 정답이 됐다.

```
보기   respected / gang / chose / conflict / and / persuaded
정답   (A) respected gang chose   (B) conflict and persuaded
```

`step_cache` 전수 실측: Q4 보기가 정답 순서와 같은 것 **740/831건(89%)**, Q5 **756/831건(91%)**.
같은 방식으로 잰 A 는 899건 중 59건(6.6%)이었다.

원인은 `_bogi_from()` 이 **토큰화만 하고 섞지 않는 것.**
A 는 바로 옆에서 시드 셔플을 하는데 B 에는 그 단계가 통째로 없었다.

→ **`variation/renderer.py` 의 `_shuffle_b_bogi()` 로 고쳤다.**
generator 가 아니라 renderer 에 넣은 이유는 — 캐시 버전을 올리면 A 까지 무효화돼
1,700여 건이 재생성되고 크레딧을 태운다. renderer 에서 섞으면 이미 쌓인 B 캐시가
**재생성 없이 다음 출력부터 바로** 정상이 된다. 운영 출력에서 확인했다.

시드는 `pid + 문항 + 정답`으로 고정한다 — 같은 문항은 몇 번을 렌더해도 같은 배열이라
시험지와 답지가 어긋나지 않는다. 한 번 섞은 데이터는 `_bogi_shuffled` 로 표시해
건너뛴다(두 번 섞으면 입력 순서가 달라져 결과도 달라진다).

`_s161` 에서 Q4 가 어법으로 바뀌어 보기가 없어졌으므로, 지금 이 셔플이 도는 것은
**Q5 하나**다.

멀쩡히 있었다.

## 11. 검수

2회독 결과물 검수는 **`variation-qa` 스킬**을 쓴다.
빈칸·보기·정답 노출·문항 간 겹침·원문 복원·B 4번 어법까지 기계로 검사한다.

**수정 기준은 하나다 — 학생이 시험지를 풀어서 낸 답과 답지가 갈리는 것만 고친다.**
힌트가 조금 새는 정도(오답 자리 낱말 겹침 등)는 그냥 둔다.

현재 운영 방침은 **HTML 수정본이 산출물**이다(코드 수정이 아니라).
검수 파이프라인: 기계 검수 → Supabase 원문 MD5 대조 → 구조 감사(복원 가능·근거 위치·누출)
→ **직접 시험지를 풀어 본다**(이게 제일 많이 잡는다) → HTML 수정 → 재검수.

발동 마커: "변형문제 — 유형 A/B", `psg-chunk`, `bogi-label`, "Q3.어휘"
Lv.1~Lv.10 표기의 1회독 워크북에는 쓰지 않는다.

### 원문은 Supabase 에서 직접 가져온다

**"원문이 없어 못 함"이라고 쓰기 전에 반드시 `passages` 테이블을 본다.**
산출물 헤더(`hdr-right`)에 `교재 · 단원 번호` 가 그대로 찍혀 있다.

```sql
select unit||' '||pid as ref, split_part(passage_text,'###해석###',1) as en
from public.passages where book = '<헤더의 교재명>' order by unit, pid;
```

대조 셋: **순서를 이으면 원문이 복원되는가 / 빈칸 정답이 원문 그대로인가 /
밑줄의 '원문어'가 원문에 실재하는가.** 이걸 건너뛰면 구조 오류를 통째로 놓친다.

### 학교명을 확인한다

시험지·답지 헤더의 학교명이 맞는지 본다. 다른 학교 이름이 박혀 나간 적이 있다
(원미고1 시험지에 '계남고1' 6곳). 생성 때 넘긴 값이라 코드로는 안 잡힌다.

### 검사기 오탐 — 실측으로 확인된 것

| 걸리는 것 | 왜 오탐인가 |
|---|---|
| 밑줄 앞 관사가 원문과 다름 (`a limited` → `an ample`) | 코드가 **시험지에 나가는 낱말**에 맞춰 고쳐 준 것이다. 학생이 관사를 되돌릴 일이 없어 답이 안 갈린다 |
| 빈칸이 `-ly` 부사로 끝남 | 원문에서 **그 문장이 거기서 끝나면** 쪼갤 뒤 낱말이 없다. 원문을 보고 판단할 것 |
| 진술이 Q3 정답 자리 낱말을 씀 | 진술이 **그 자리에 기대지 않으면** 답이 안 갈린다. 근거 문장이 실제로 뒤집힌 문장인지 확인할 것 |

### B 4번 어법은 형태만 기계가 본다

검사기가 보는 것: 답지에 '틀린 표현 → 고친 것' 이 있는가 / 틀린 표현이 본문에
낱말 경계까지 맞춰 **딱 한 번** 심겼는가 / 바른 형태가 본문에 남아 있지 않은가 /
오류가 1번의 주어진 문장 안이 아닌가 / 이유 모범답안과 어법 이름이 있는가 /
`--orig` 가 있으면 심은 오류를 되돌렸을 때 원문과 같은가.

**어법 판단 자체는 코드가 못 한다.** 아래는 문장에 넣어 읽어야 보인다:

- **심은 오류가 정말 틀렸는가.** 두 형태가 다 맞는 자리면 문항이 성립하지 않는다
  (start + to V/V-ing, 주격 that/which, 목적격 who/whom).
- **어휘·의미 차이를 어법이라고 낸 건 아닌가.** 시제 바꾸기, 부정 붙이기,
  접두사 교체, 불가산명사에 s 는 어법 문항이 아니다.
- **바로 옆에 단서가 있지 않은가.** 조동사 뒤, 주어 바로 뒤 수일치는
  구조를 안 읽고 형태만 보고 1초에 풀린다.
- **이유 모범답안이 실제 근거를 대는가.** "과거분사를 써야 한다"만 있고
  왜 그런지가 없으면 채점 기준이 안 선다.

★ 산출물에 **요약문이 두 개** 보이면 옛 캐시다. 검사기가 잡아 준다.

### 검사기가 못 잡는 것 — 눈으로 봐야 한다

**Q4 진술이 Q5 정답을 '표현만 갈아입혀' 재현하는 경우**(유형 A).
검사기는 내용어 4연속 일치로 보는데, 말을 바꿔 쓰면 그 검사를 빠져나간다.

```
진술 다      depends on what it will be used for
Q5(B) 정답   depends on what I'm intending to do with it
```
실측(25년 고1 9월 33번): 검사기 무반응. 답지의 근거 인용문과 Q5 정답을 나란히 놓고
눈으로 대조해야 잡힌다. **답지 근거가 빈칸 자리 문장이면 그 진술은 판단 불가다.**
